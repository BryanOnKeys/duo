## 2. Detailed Case Analysis

### 2.1 Case `L4` — False Positive on Importer Scope (`S15P31A106-264`)

#### Minimal Reproduction
- **Decision `D-001`**:
  - `governs.paths: ["src/ui/**"]`
  - `forbids.imported_paths: ["src/db/legacy-db.ts"]`
  - `enforcement: block`
- **Diff**: Add `src/services/archive.ts` containing `import { legacyQuery } from "../db/legacy-db.js";`.
- **Actual 0.3.3 Result**: `verdict: "BLOCK"`, 1 `decision-forbids-import` claim (`provenance: "introduced"`, `blockEligible: true`).
- **Expected Result**: `verdict: "PASS"` (architectural rule allows `src/services/**` to call `src/db/legacy-db.ts` while forbidding `src/ui/**`).

#### Code Trace
1. In [`packages/director/src/review/rules.ts`](../../packages/director/src/review/rules.ts) (`decisionForbidsImport`, lines 443–467), the rule iterates over all active Decisions with `d.forbids.importedPaths.length > 0` and then iterates over **every** analyzable changed file `f` in `usable`:
   ```ts
   for (const f of usable) {
     const lines = changedNewLineSet(f);
     ...
     for (const ref of fileRefs.get(f.path) ?? []) {
       if (!overlapsLines(lines, ref.range.startLine, ref.range.endLine)) continue;
       ...
       if (!matchesAnyRepoGlob(ref.target, d.forbids.importedPaths)) continue;
   ```
2. `d.governs.paths` is never consulted in `decisionForbidsImport` (nor in `decisionForbids` for identifier/symbol tokens, lines 387–436).
3. This matches the 0.3.0 / 0.3.3 contract recorded in [conflicts.md](../conflicts.md) (H-72) and [0.3.0-t40-rc-blockers.md](0.3.0-t40-rc-blockers.md) (N3): `governs.paths` declares which paths a Decision is about for Context compilation and Governance discovery, whereas `forbids` applies repository-wide (`Forbids scope: repository-wide (governs does not narrow forbids)`).
4. Because [`DecisionSchema`](../../packages/core/src/schema/schemas.ts) (`packages/core/src/schema/schemas.ts`, lines 171–180) only has `dependencies`, `symbols`, `paths`, and `imported_paths` inside `forbids`, a user cannot express a layer-boundary rule ("files in `src/ui/**` must not import `src/db/legacy-db.ts`, but `src/services/**` may") without triggering a false positive in `src/services/**`.

#### Classification & Follow-up Proposal
- **Classification**: **Documented contract limit in 0.3.3; fixable in 0.4 via Decision schema extension.**
- **Why not implicitly use `governs.paths` to filter `forbids`?**
  - Changing `governs.paths` to silently narrow `forbids` would break existing Decisions where `governs.paths` points to the module being protected (e.g., `governs.paths: ["src/db/legacy-db.ts"]` + `forbids.imported_paths: ["src/db/legacy-db.ts"]`). In that common pattern, restricting `forbids` to importers inside `governs.paths` would stop checking `src/ui/**` altogether!
- **Recommended 0.4 Follow-up**:
  - Add an explicit optional field on `forbids` (e.g., `importer_paths?: RepoGlob[]` or `in_paths?: RepoGlob[]`, and optionally `except_paths?: RepoGlob[]`) in `DecisionSchema`, included in `decisionLockDigest`, and checked against `f.path` in `decisionForbidsImport` (and `decisionForbids`).

### 2.2 Case `D3` — False Negative on Second Forbidden Import in Baseline-Exempt File (`S15P31A106-265`)

#### Minimal Reproduction
- **Baseline State (`HEAD`)**: `src/ui/legacy-orders-page.ts` already contains `import { legacyQuery } from "../db/legacy-db.js";` on line 1, and an Adoption Baseline has been captured.
- **Diff (`WORKTREE`)**: Keep line 1 and add a **second** import statement on line 2:
  ```ts
  import { legacyQuery } from "../db/legacy-db.js";
  import { legacyQuery as legacyCount } from "../db/legacy-db.js";
  ```
- **Actual 0.3.3 Result**: `verdict: "WARN"`, 1 claim with `provenance: "pre-existing-touched"` and `blockEligible: false`.
- **Expected Result**: `verdict: "BLOCK"` (`provenance: "introduced"`, `blockEligible: true`) because a brand-new forbidden import statement was added.

#### Code Trace
1. **Baseline Key Granularity**: In [`packages/director/src/adoption/head.ts`](../../packages/director/src/adoption/head.ts) (`headBaselineFindings`, lines 112–120), baseline findings for `decision-forbids-import` are recorded per unique `File -> File` `IMPORTS` edge in the Graph:
   ```ts
   const key = violationKey("decision-forbids-import", d.id, `import:${edge.from}->${edge.to}`);
   ```
   No statement count, specifier list, or line digest is stored in the baseline finding.
2. **Review Rule Grouping**: In [`packages/director/src/review/rules.ts`](../../packages/director/src/review/rules.ts) (`decisionForbidsImport`, lines 462–488), all changed module references in `f.path` that resolve to `ref.target` under Decision `d.id` are merged into a single group `k = "${d.id}\0${f.path}\0${ref.target}"` with the same pair-level key:
   ```ts
   violationKey("decision-forbids-import", g.decision.id, `import:${fileNode(g.source)}->${fileNode(g.target)}`)
   ```
   and `touched: true`.
3. **Provenance Classification**: In [`packages/director/src/review/claims.ts`](../../packages/director/src/review/claims.ts) (`makeClaim`, lines 84–92):
   ```ts
   const provenance = !hasBaseline ? undefined
     : !covered ? "unverified-at-adoption"
     : ctx.baselineKeys.has(v.key) ? (v.touched ? "pre-existing-touched" : "pre-existing-untouched")
     : "introduced";
   ```
   Because `ctx.baselineKeys.has(v.key)` is `true` and `v.touched` is `true`, the new import statement inherits `"pre-existing-touched"`, which sets `blockEligible = false` and downgrades the review verdict from `BLOCK` to `WARN`.

#### Classification & Follow-up Proposal
- **Classification**: **Fixable in 0.4** (within `packages/director/src/review/rules.ts` without even requiring an Adoption Baseline schema migration).
- **Recommended 0.4 Follow-up**:
  - When `ctx.baselineKeys.has(pairKey)` is `true` for `(d.id, f.path, ref.target)`, inspect the `ctx.from` (`HEAD`) version of the file (`sideText(ctx, ctx.from, f.oldPath ?? f.path)` or `from` module references):
    - If the total count of import statements in `f.path` targeting `ref.target` (or the count of statements matching `d.forbids.importedPaths`) **increased** relative to `ctx.from` (or if a changed import statement was inserted on a hunk where `oldLines === 0` while all pre-existing import statements in `ctx.from` remain intact), classify the net-new import statement as `introduced` (e.g., by not matching the baseline exemption or by appending a statement ordinal `#2` to the violation key for net-new edges beyond the `HEAD` count).

### 2.3 Case `L1` — False Negative on Barrel Re-export (`S15P31A106-266`)

#### Minimal Reproduction
- **Barrel File**: `src/db/index.ts` contains `export { legacyQuery } from "./legacy-db.js";`.
- **Diff**: Add `src/ui/report-page.ts` containing `import { legacyQuery } from "../db/index.js";`.
- **Actual 0.3.3 Result**: `verdict: "PASS"`, 0 claims, 0 limitations.
- **Expected Result**: Either `BLOCK` (recognizing that the imported binding `legacyQuery` resolves through `src/db/index.ts` to `src/db/legacy-db.ts`) or an explicit limitation indicating barrel re-exports were not transitively checked.

#### Code Trace
1. **1-Hop Module Resolution**: In [`packages/graph/src/incremental/references.ts`](../../packages/graph/src/incremental/references.ts) (`readIndexedModuleReferences`, lines 51–76), each `SourceAnalysis.moduleReferences[j]` is paired with `FileResolution.modules[j]`:
   ```ts
   ...(m?.status === "resolved" ? { target: m.target } : {}),
   ```
   For `import { legacyQuery } from "../db/index.js"`, `m.target` is `"src/db/index.ts"`.
2. **Direct Target Glob Match Only**: In [`packages/director/src/review/rules.ts`](../../packages/director/src/review/rules.ts) (`decisionForbidsImport`, line 461):
   ```ts
   if (!matchesAnyRepoGlob(ref.target, d.forbids.importedPaths)) continue;
   ```
   Because `"src/db/index.ts"` does not match `["src/db/legacy-db.ts"]`, the reference is skipped.
3. **Existing Re-export Machinery in `@duo-director/graph`**:
   - Notably, [`packages/graph/src/build/exports.ts`](../../packages/graph/src/build/exports.ts) (`ExportIndex.find`, lines 58–114) **already** resolves re-export chains up to `MAX_REEXPORT_DEPTH = 4` (handling `export { x as y } from "./mod"` and `export * from "./mod"`).
   - However, `ExportIndex` is currently used only inside [`packages/graph/src/build/collect.ts`](../../packages/graph/src/build/collect.ts) to resolve `CALLS` edges to their defining symbol; the resolved defining file for each imported binding in `moduleReferences[j].bindings` is not persisted in `FileResolution` or exposed by `readIndexedModuleReferences`.

#### Classification & Follow-up Proposal
- **Classification**: **Documented limit in 0.3.3 (H-72); fixable in 0.4 for static re-exports in TS/JS/Python.**
- **Recommended 0.4 Follow-up**:
  - **Option L1-A (Binding-level re-export target resolution — Recommended)**: During Graph resolution (`packages/graph/src/build/collect.ts`), resolve each `ExtractedImportBinding` via `ExportIndex.find(targetFile, binding.importedName)` (already bounded by `MAX_REEXPORT_DEPTH = 4`) and record any distinct re-exported origin `RepoPath`s on `ResolvedModuleReference` (e.g., `reexportTargets?: readonly RepoPath[]`). `decisionForbidsImport` can then match both `ref.target` and `ref.reexportTargets` against `d.forbids.importedPaths`, citing the barrel chain (`src/ui/report-page.ts:1 import "../db/index.js" -> src/db/index.ts re-exports src/db/legacy-db.ts`) in `observed` and `evidenceIds`.
  - **Option L1-B (Namespace / side-effect import fallback)**: When `import * as db from "../db/index.js"` imports a barrel file that itself has an outgoing `IMPORTS` edge to a forbidden path via re-export (`exportKind === "reexport"` or `"star-reexport"`), either match transitively or emit a specific limitation (`imports-reexport-chain`).

### 2.4 Case `L2` — False Negative & Missing Limitation on Computed / Template Dynamic Import (`S15P31A106-267`)

#### Minimal Reproduction
- **Scenario L2a (Computed dynamic import)**:
  - Add `src/ui/lazy-page.ts` with `return import(\`../db/${name}.js\`);`.
  - **Actual 0.3.3 Result**: `verdict: "PASS"`, 0 claims, **0 limitations** (`importLimits(res)` is `[]`).
- **Scenario L2b (Static no-substitution template literal dynamic import)**:
  - Add `src/ui/lazy-static-template.ts` with ``return import(`../db/legacy-db.js`);``.
  - **Actual 0.3.3 Result**: `verdict: "PASS"`, 0 claims, **0 limitations**.

#### Code Trace
1. In [`packages/analyzer/src/language/tree-sitter/ts-js-extract.ts`](../../packages/analyzer/src/language/tree-sitter/ts-js-extract.ts) (`Extractor.call`, lines 656–668):
   ```ts
   const only = args?.type === "arguments" && args.namedChildren.length === 1 ? args.namedChildren[0] : undefined;
   if (fn.type === "import") {
     if (only?.type === "string") this.module(node, only, "dynamic-import", false, []);
     return;
   }
   if (fn.type === "identifier" && fn.text === "require" && only?.type === "string") {
     this.module(node, only, "require", false, this.requireBindings(node));
     return;
   }
   ```
2. This causes two distinct defects:
   - **Defect L2b (Static template literal ignored)**: In Tree-sitter TS/JS, `` `../db/legacy-db.js` `` has `only.type === "template_string"`, not `"string"`. Even though `literalText(node)` at lines 98–102 of the exact same file (`ts-js-extract.ts`) already handles `template_string` nodes without `template_substitution`:
     ```ts
     function literalText(node: SyntaxNode | null | undefined): string | undefined {
       if (!node) return undefined;
       if (node.type === "string") return unquote(node.text);
       if (node.type === "template_string" && !node.namedChildren.some((c) => c.type === "template_substitution")) return unquote(node.text);
       return undefined;
     }
     ```
     `Extractor.call` checks `only?.type === "string"` instead of `literalText(only) !== undefined`, so ``import(`../db/legacy-db.js`)`` is silently dropped.
   - **Defect L2a (Computed dynamic import emits no module reference and no limitation)**: When `only` is a template literal with substitutions (`` `../db/${name}.js` ``) or a variable/expression (`import(spec)`), `if (fn.type === "import")` hits `return;` without recording an `ExtractedModuleReference`. Consequently, `FileResolution.modules` has no entry, and `decisionForbidsImport` (`packages/director/src/review/rules.ts`, lines 452–459) never reaches the `ref.status === "unresolved"` branch that emits the `imports-unresolved` limitation.

#### Classification & Follow-up Proposal
- **Classification**:
  - **Resolving arbitrary runtime expressions (`import(variable)`)**: **Out of static analyzer scope**.
  - **Extracting static template literals (`L2b`) and surfacing computed dynamic imports as an `imports-unresolved` limitation (`L2a`)**: **Fixable in 0.4**.
- **Recommended 0.4 Follow-up**:
  1. In `Extractor.call` (`packages/analyzer/src/language/tree-sitter/ts-js-extract.ts`), check `literalText(only) !== undefined` for both `import(...)` and `require(...)` so no-substitution template literals (`L2b`) are extracted and resolved identically to string literals.
  2. When `fn.type === "import"` (or `require`) has an argument where `literalText(only) === undefined`, either emit an `ExtractedModuleReference` with a non-resolvable marker (or `dynamicComputed: true`) so Graph resolution marks it `status: "unresolved"` (`reason: "dynamic-specifier"`), allowing `decisionForbidsImport` to surface `imports-unresolved` on changed lines without guessing targets.
